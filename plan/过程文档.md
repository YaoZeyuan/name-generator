### 规则能力

旧版已实现或已有资料支撑的规则：

1. 过滤非汉字。
2. 过滤或指定多音字发音。
3. 避开指定同音字。
4. 检查同音。
5. 检查同声调。
6. 检查声母发音方法和发音部位是否重复。
7. 检查韵母类别是否重复。
8. 支持指定字出现在第二位或第三位。
9. 支持姓氏末字为多音字时手动确认读音。

### 前端能力

旧版前端可作为交互原型参考：

1. 姓氏输入。
2. 避讳字输入。
3. 指定字输入。
4. 指定字位置选择。
5. 候选来源选择。
6. 偏男宝、偏女宝、都看看过滤。
7. 候选名生成。
8. 候选名下载。

当前前端实现方向改为 Taro 4 + Vue 3。`old/` 中的前端代码只作为逻辑和交互参考，不作为继续维护的主工程。

## 4. 决策记录

### D001：项目目标

状态：已确认

项目不以商业化为目标，重点是实际解决起名字问题。

### D002：核心问题

状态：已确认

项目只解决可以量化的三件事：

1. 音律得当。
2. 绕过避讳。
3. 最好有含义。

### D003：推荐主线

状态：已确认

主线从「枚举生成所有可能」转为「从高质量既有名字中筛选和重组」。

### D004：工程方向

状态：已确认

使用 Taro 4 + Vue 3 作为前端底层框架。`src/` 仅作为 Taro 前端目录。平台无关核心逻辑放到 `packages/name-core/`。

### D005：数据目录

状态：已确认

原始数据保存在 `resource/`，不移动。清洗后的数据放在 `database/`。统一候选库放在 `database/candidate/`。

### D006：实现路径

状态：已确认

先做工程整理、统一候选名数据库和 JSON 配置式 CLI 验证器；CLI 推荐质量稳定后再接 Taro 前端。

### D007：大模型和 embedding

状态：已确认

第一版不依赖大模型，不做 embedding 推荐。允许导出对名字的评价，方便后续人工筛选。

### D008：默认来源优先级

状态：已确认

默认优先级：

```text
财富论-精选集
  -> 财富论-集思录
  -> 五道口-精选集
  -> 五道口-集思录
  -> 他山石
  -> 登科录
  -> 古人云
```

### D009：输出数量

状态：已确认

第一版 CLI 默认输出 30 个候选名。

### D010：前端倾向文案

状态：已确认

前端使用「响亮 / 柔和 / 不限」，并说明其大致对应偏男宝、偏女宝、不限。

## 5. 评分调参样例

正向样例：

1. 姚瑾瑞
2. 钱弘俶
3. 尧歌游

反向样例：

1. 赵钱孙
2. 刘强
3. 李建国

使用方式：

1. 正向样例用于检查推荐解释是否合理。
2. 反向样例用于检查风险过滤、俗套降权、三字名目标约束是否有效。
3. 样例只作为评分方向参考，不直接等同最终白名单或黑名单。
